## 单笔巨额亏损风控（livesafe 预设已启用）

| 开关 | 默认（livesafe） | 说明 |
|---|---|---|
| `PM_Enable` | true | 开启逐仓硬性止损 |
| `PM_MaxPositionLossPct` | 8.0 | 任一持仓浮亏达到净值的 8% 立即平仓（随账户缩放） |
| `PM_MaxPositionLossUSD` | 0 | 可改为绝对金额封顶，如 50 = “单笔最多亏 50 美元” |
| `PG_Enable` | true | 本金保护：净值低于本金时逐步降仓 |

调紧（如 PM 5%）会更安全但短窗口易频繁止损（churn）；PM 8% 是全周期最优点。小账户/保守可用
`PM_MaxPositionLossUSD` 设硬封顶。

## 关于回撤的诚实说明

- 已系统测试 ~12 种回撤/灾难风控（逐仓封顶、连败冷却、开仓止损、时间止损、VRP、去 MU、入场 SL、
  DD 降仓、杠杆/净值门控…）：除 PM 外，均在**全周期真实 Tick**上使结果变差。
- 根因：子策略是**均值回归**——回撤后跟着反弹；在回撤中降仓/止损会错过反弹，这正是其盈利来源。
- 因此 ~30% 净值回撤、以及 2023 类震荡期入场的本金回撤，是**结构性**的，无法在不摧毁优势的前提下消除。
- 真正能降低你**体感回撤**的只有：（a）降低 `URF_BaseScale`（整体缩小）；（b）定期提取利润、不复利。

## 月度熔断（Month-Lock）说明 —— 针对“6 月初被简单粗暴熔断”的调查

**现象**：`GRM_MonthlyLossLimitFreeMarginPct=3.0` 在 $3000 小账户上，阈值 = 自由保证金 × 3% ≈ **$85**。
用调试日志复现（tester journal，注意日志是 UTF-16，需先 `iconv -f UTF-16LE` 再 grep），确认熔断在
**2026.06.01 22:00** 就触发：`monthPL=-84.79 <= -84.71 limit`——**6 月第一天一笔小亏就触发**。你说它
“简单粗暴”在机制上完全正确。

**但两点需澄清（Model=4 真实 Tick 一篮子）**：
1. 它是**动态闸门**，不是把整月锁死：当本月已实现盈亏回到 −$85 以上时会**自动重新开仓**，所以 6 月**仍在交易**。
2. 6 月其实是**盈利月**，且**带熔断时更赚**：6 月 = **+2,888（带锁）** vs +2,197（不带锁）；7 月 ≈ 持平（−110）。
   你在本地看到的“7 月连续亏损”很可能来自 **XAUUSD 单图 Model=1**，与真实 Tick 一篮子不同。

**阈值扫描（全周期真实 Tick）——阈值非单调，3% 已是最优**：

| 月度熔断阈值 | 净利润 | 净值回撤 | PF | 交易数 |
|---|---|---|---|---|
| **3%（当前 livesafe）** | +109,877 | **29.54%** | **1.43** | 3912 |
| 10% | +91,109 | 38.48% | 1.29 | 5244 |
| **0%（关闭熔断）** | **+134,605** | 34.78% | 1.35 | 6076 |

> 10% 反而是三者中**最差**（净利更低、回撤更高）——所以“调高阈值”不是有效修复。
> **3% 是风险调整后的最优点**（最高 PF、最低回撤），故 livesafe 保持 3% 不变。

**可选：最大收益模式（愿意承受更高回撤者）**：在 livesafe 基础上设
`GRM_MonthlyLossLimitFreeMarginPct=0` → **+134,605 / 净值回撤 34.78%**（比带锁多赚 ~24.7k，回撤高 ~5pp）。
这会让 livesafe 变成“高收益高回撤”，与其“稳健”定位相悖，故不作默认；如需最大收益也可直接用 `champion.set`。
